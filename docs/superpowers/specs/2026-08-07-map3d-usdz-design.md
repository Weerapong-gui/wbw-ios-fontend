## 2. โมเดลที่จะใช้ — ข้อเท็จจริงที่ตรวจแล้ว

ตรวจด้วย `usdcat ~/Downloads/map.usdz`:

- export จาก **Blender 5.2.0 LTS**, `metersPerUnit = 1`, `upAxis = "Z"`, defaultPrim `root`
- กลุ่มระดับบน: `Buildings` (mesh รวมทั้งไฟล์ **1,906** ชิ้น), `Roads`, `LandCover`, `Water`,
  `tinMesh` + `tinMesh_001` (ภูมิประเทศ), `Area`, `clippedBottom`, `clipSide`
- texture 2 ไฟล์ในแพ็กเกจ: `groundForestBaked.png` (6.5 MB), `waterRippleNormal.png` (230 KB)
- วัสดุตั้งชื่อแบบ maps3d.io: `bldg_terracotta`, `bldg_ochre`, `bldg_sage`, `bldg_cream`,
  `bldg_rose`, `roadGroup_arterial_flat`, `landCoverMaterial_FARMLAND_…`, `waterMaterial_…`
- **แท่งทรงกระบอกแดง 8 แท่ง** — prim ชื่อ `Cylinder`, `Cylinder_001` … `Cylinder_007`
  วัสดุ `cylinderRedMaterial` (สีแดง `0.604, 0.022, 0.015`)
  ทุกแท่ง scale `(33.37, 33.37, 253.40)` และ Z เท่ากันที่ `-78.966`
  ต่างกันแค่ตำแหน่ง XY เช่น `(951.96, 874.74)`, `(216.25, -1196.18)`, `(-752.70, -893.52)`
- `Area` scale `1922.11` → พื้นที่รัศมีราว 1.9 กม.

จำนวนแท่ง 8 ตรงกับจำนวนฐานเช็คอิน แต่ **ชื่อ prim ไม่ได้บอกว่าแท่งไหนคือฐานไหน**
การจับคู่จึงต้องทำเองและพิสูจน์ด้วยตา (§6)

## 3. เป้าหมาย

แท็บ Map เป็นโมเดล 3D ของพื้นที่งาน แทน MapLibre ทั้งหมด:

1. **ดูโมเดล** — orbit + pinch zoom ผ่าน RealityKit camera controls กล้องเริ่มต้นเอียงมองลงมา
2. **แตะหมุดแล้วขึ้นชื่อฐาน** — แตะแท่งแดงแล้วมีการ์ดเล็กบอกชื่อฐานกับลำดับ
3. **จุดตำแหน่งเรา** — จุดตาม GPS บนโมเดล ซ่อนเมื่ออยู่นอกพื้นที่หรือไม่ให้สิทธิ์
4. **เครดิตข้อมูล** — overlay ตัวเล็กมุมล่าง (§7)

### ไม่ทำ (YAGNI)

- ไม่มีไทล์แผนที่สด ไม่มี MapLibre — ถอด dependency ออกจาก `project.yml`
- ไม่โชว์สถานะเช็คอินบนหมุด (เฟสหลัง ถ้าอยากได้)
- ไม่มีเส้นทางนำทาง ไม่มีค้นหา ไม่มีโหมด AR
- ไม่โหลดโมเดลจากเน็ตตอนรัน — usdz อยู่ในบันเดิล
- ไม่แตะ backend ทั้งสองรีโป ไม่เพิ่ม endpoint ใหม่

## 4. สถาปัตยกรรม

โหลดโมเดลด้วย `Entity(named: "map")` แบบเดียวกับที่ `ForestSceneView.swift:49` โหลด `forest.usdz`
`WBW/Resources/` ถูกรวมเป็น sources ของ target อยู่แล้ว (`project.yml:18-19`) ไฟล์ใหม่เข้า target
เองหลัง `xcodegen generate`

**ไม่มี host/claim/release แบบฉากป่า** — `ForestSceneHost` มีอยู่เพราะหลายจอใช้ฉากเดียวกัน
และฉากต้องอยู่ใต้ `RootView` คนละต้นไม้กับจอ แผนที่อยู่จอเดียว `RealityView` เกิดและตายไปกับ
`Map3DScreen` ตรงๆ ไม่ต้องยืมกลไกนั้นมา

### สิทธิ์ตำแหน่ง

เคยมี `NSLocationWhenInUseUsageDescription` ค้างอยู่ทั้งที่ไม่มีไฟล์ไหน import CoreLocation
จนต้องเขียนเทสคุมไว้ที่ `WBWTests/AppStoreConfigTests.swift:65` คอมเมนต์ของเทสนั้นเขียนไว้เองว่า
*"ถ้าวันหนึ่งเพิ่มฟีเจอร์แผนที่จริง ให้ลบเทสนี้พร้อมกับตอนเติมคีย์กลับ"* — งานนี้คือกรณีนั้น
เปลี่ยนข้อความยืนยันให้บังคับว่า**ต้องมี**คีย์ตำแหน่งแทน ส่วน `NSPhotoLibraryUsageDescription`
ยังต้องห้ามมีเหมือนเดิม และอีกเทสในไฟล์เดียวกันบังคับให้ Info.plist กับ Info-Debug.plist
มีคีย์ตรงกัน จึงต้องเติมทั้งสองไฟล์

### พิกัดโมเดล (ยังค้าง)

`Map3DGeo` ต้องรู้ว่าขอบโมเดลตรงกับ lat/lng ช่วงไหน ค่านี้อยู่ในไฟล์ export ที่ Park กำลังหา
(`maps3d.json` หรือไฟล์ `.blend`) **Task ที่ไม่ใช่จุด GPS ทำได้เลยโดยไม่ต้องรอ**

ถ้าหาไม่เจอ ทางสำรองคือใช้ bbox จาก export รอบ 2026-07-18 ที่สเปกเก่าบันทึกไว้
(SW `20.02371, 99.88272` / NE `20.06727, 99.92288`, EPSG:3857, local origin) **แล้วต้องเขียน
กำกับในโค้ดและในเอกสารยืนยันว่าเป็นค่าที่สมมติจาก export คนละรอบ** ยังไม่ได้พิสูจน์ —
พิสูจน์จริงได้ทางเดียวคือยืนที่ฐานบนดอยแล้วดูว่าจุดตรงไหม

## 5. สวิตช์ `Config.map3D` — ทำไมถึงบังคับ

วันนี้ (2026-08-07) เพิ่งปิดฉากป่า 3D ทั้งสายด้วย `Config.forest3D = false` เพราะเครื่องทำงานหนัก
และ `docs/forest-3d-off-verification.md` §7 บันทึกไว้ตรงๆ ว่า **ยังไม่มีตัวเลขยืนยันว่าฉากคือ
ตัวการจริง** — โมเดลนี้หนักกว่าฉากป่ามาก (1,906 mesh + texture 6.5 MB เทียบกับ `forest.usdz` 647 KB)

จึงต้องมีสวิตช์แบบเดียวกันตั้งแต่ commit แรก ไม่ใช่ตามไปเติมทีหลัง:

- `Config.map3D = true` เป็นค่าเริ่มต้นของงานนี้ (ต่างจาก `forest3D` ที่ตั้ง false)
- ปิดแล้วแท็บ Map ต้องเหลือของที่ใช้งานได้ — การ์ดข้อความบนพื้น `Color.wbwForestVoid`
  ว่าแผนที่ปิดชั่วคราว **ไม่ใช่จอว่างหรือจอขาว**
- ตรรกะสวิตช์เป็นฟังก์ชันบริสุทธิ์ที่เทสได้ ทรงเดียวกับ `ForestSceneHost.shouldClaim`

ถ้าวัดแล้วโมเดลหนักเกินรับ ทางลดคือกลับไปลด mesh ใน Blender (join อาคารเป็นก้อนเดียว
ลดขนาด texture) **ไม่ใช่แก้โค้ดฝั่งแอป**

## 6. หมุดฐาน

- หา entity ด้วย `root.findEntity(named:)` ทรงเดียวกับ `ForestSceneView.swift:126`
- ใส่ `CollisionComponent` + `InputTargetComponent` ให้แต่ละแท่ง แล้วรับแตะด้วย
  `SpatialTapGesture` ที่ `RealityView`
- **ชื่อฐานมีให้เฉพาะฐานที่เช็คอินไปแล้ว** — `GET /wbw/me/progress` คืน `{total, checked_in[]}`
  เท่านั้น (`WBW/Models.swift:286`) แต่ละแถวมี `name`/`sequence` ส่วน `CheckinProgress.pending`
  ที่มีอยู่ **ไม่ใช่** ฐานที่ยังไม่เดินไปถึง — มันคือฐานที่เช็คอินแล้วแต่ยังไม่ได้ให้ความเห็น
  ลิสต์ชื่อฐานทั้งหมดอยู่ที่ `GET /wbw/staff/checkpoints` ซึ่งเป็น staff/admin เท่านั้น
  (`docs/backend-contract.md:50`) participant เรียกไม่ได้
- ดังนั้นการ์ดชื่อฐานทำงานสองแบบ: ฐานที่เช็คอินแล้ว → ชื่อจริงจาก `CheckinProgressStore`
  ฐานที่ยังไม่เช็คอิน → `"ฐานที่ N"` ตามลำดับในตาราง **ห้ามฮาร์ดโค้ดชื่อฐานเดา**
  ถ้าอยากได้ชื่อครบต้องเปิด endpoint ฝั่ง participant ก่อน ซึ่งอยู่นอกขอบเขตงานนี้
- จับคู่ prim ↔ ลำดับฐานด้วยตารางฮาร์ดโค้ดใน `Map3DPins.swift` เพราะโมเดลตั้งชื่อว่า
  `Cylinder_004` ไม่ได้บอกว่าเป็นฐานไหน — **คู่ที่ถูกต้องยืนยันด้วยสกรีนช็อตเท่านั้น**

**ต้องยืนยันกับ Park ก่อนเขียนข้อความนี้ลงจอ** ว่า export รอบ 2026-08-07 ใช้ imagery
ตัวเดียวกันจริง ถ้าเปลี่ยนแหล่งไป ข้อความเครดิตต้องเปลี่ยนตาม

## 8. Error handling

- โหลด `map.usdz` ไม่สำเร็จ → ข้อความบอกว่าโหลดแผนที่ไม่ได้ + ปุ่มลองใหม่ ไม่ crash
  (ฉากป่ามี `loadFailed` เป็นแบบอ้างอิง)
- ไม่ได้สิทธิ์ตำแหน่ง หรือ GPS ล้มเหลว → ไม่โชว์จุด เงียบๆ จอที่เหลือใช้ได้ปกติ
- อยู่นอก bbox → ไม่โชว์จุด (คนใช้แอปจากบ้านก่อนวันงานเป็นเรื่องปกติ)

## 9. Testing

**เทสยูนิต** (`WBWTests`)

- `Map3DGeo` — ยิงมุม bbox ทั้งสี่ + จุดกลาง ต้องลงตรงขอบ/กลางโมเดลตามคาดภายใน tolerance
  และจุดนอก bbox ต้องถูกรายงานว่าอยู่นอก
- สวิตช์ `Config.map3D` — ตรรกะเดียวกับ `ForestSceneHostTests`
- `Map3DPins` — ตารางจับคู่ต้องครบ 8 ไม่ซ้ำ ไม่มีลำดับหาย

**ยืนยันด้วยตาบนซิม** — โมเดลขึ้นจริงไม่ใช่จอเปล่า, texture ติด, หมุดครบ 8,
เครดิตอยู่มุมล่าง, การ์ดชื่อฐานโผล่ถูกฐาน

การแตะบนซิมทำ headless ไม่ได้ (สภาพแวดล้อมนี้ไม่มี tap tooling — ดู
`docs/forest-3d-verification.md:61`) ต้องมี launch flag เปิดการ์ดตรงๆ ทรงเดียวกับ
`uitestChat` / `uitestFeedback` ที่ `MainTabView.swift`

**วัดบนเครื่องจริง — เงื่อนไขจบงาน** เทียบ CPU/ความร้อนของแท็บ Map เดิม (MapLibre)
กับโมเดลใหม่ เขียนผลลง `docs/map3d-verification.md` โครงเดียวกับ

## 10. ความเสี่ยง

1. **โมเดลเรนเดอร์ไม่ออกหรือ texture พัง** — ความเสี่ยงอันดับหนึ่ง ทำเป็น Task แรกและทำลำพัง
   ถ้าพัง แก้ที่ Blender ไม่ใช่ที่โค้ด
2. **เครื่องหนักกว่าเดิม** — §5 ครอบไว้แล้วด้วยสวิตช์ + การวัด
3. **จับคู่หมุดผิดฐาน** — ตารางฮาร์ดโค้ดที่พิสูจน์ด้วยตาเท่านั้น ผิดแล้วคนเดินผิดฐานจริง
   ต้องให้ Park ยืนยันคู่จากสกรีนช็อตก่อนปิดงาน
4. **bbox เป็นค่าสมมติ** — ถ้าต้องใช้ทางสำรอง จุด GPS จะเพี้ยนโดยไม่มีอะไรฟ้อง
   ต้องเขียนกำกับไว้ทั้งในโค้ดและเอกสาร
5. **ถอด MapLibre แล้วถอยยาก** — เก็บ `MapScreen.swift` ไว้ใน git history เท่านั้น
   ถ้าอยากถอยจริงต้อง revert commit ไม่ใช่แค่กลับ flag
