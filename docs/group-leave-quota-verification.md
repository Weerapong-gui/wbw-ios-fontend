### หลักฐานฝั่งฐานข้อมูล

อ่านจาก `group_membership_log` หลังเดินจบ — ตรงกับที่กดทุกแถว:

```
 action | group_id | quota_after | admin_ทำ | created_at
--------+----------+-------------+----------+------------
 join   |       40 |           1 | f        | 23:45:43
 leave  |       40 |           0 | f        | 23:46:06
 join   |        5 |           0 | f        | 23:46:32
```

สามอย่างที่แถวพวกนี้พิสูจน์:

- **การเข้ากลุ่มไม่หักสิทธิ์** — แถว `join` แรกมี `quota_after = 1` เท่าเดิม
- **การออกหัก 1 ครั้ง** — แถว `leave` เหลือ 0
- **เข้ากลุ่มตอนสิทธิ์หมดยังทำได้** — แถว `join` สุดท้ายผ่าน โดย `quota_after` ยังเป็น 0

`admin_ทำ = f` ทุกแถว (คอลัมน์ `actor_id` เป็น NULL) = ผู้ใช้ทำเอง ไม่ใช่แอดมินสั่ง
สถานะปลายทาง: `group_id = 5`, `leave_quota = 0`

## 2. ตรวจฝั่ง API ด้วย curl (ก่อนเดินด้วยมือ)

| เส้น | ผล |
|---|---|
| `GET /wbw/me` | 200 · มี `leave_quota` และ `membership_log: []` (เป็น array ไม่ใช่ `null`) |
| `GET /wbw/admin/participants` | 200 · 16 คีย์ต่อแถว · `leave_quota` มาครบทุกแถว ไม่มีฟิลด์เลื่อน |
| `GET /wbw/admin/participants/{id}/detail` | 200 · ไทม์ไลน์เรียงใหม่ไปเก่า มี `actor_name` |
| `PATCH .../{id}` `leave_quota: 99` | **400** `สิทธิ์ออกจากกลุ่มต้องอยู่ระหว่าง 0 ถึง 10` |
| `PATCH .../{id}` `leave_quota: 2` | 200 · ลง `group_membership_log` (`quota_adjust`, `actor_id` = แอดมิน) และ `admin_log` (`ปรับสิทธิ์ออกกลุ่ม`) |
| `POST /wbw/groups/leave` ตอนสิทธิ์หมด | **409** `สิทธิ์ออกจากกลุ่มหมดแล้ว` · สถานะไม่ขยับ |
| `POST /wbw/groups/{id}/join` ตอนมีกลุ่มอยู่ | **409** `ท่านอยู่ในกลุ่มอยู่แล้ว ต้องออกจากกลุ่มเดิมก่อน` · สถานะไม่ขยับ |

เส้น `/wbw/me` กับ `/wbw/admin/participants` สำคัญเป็นพิเศษเพราะเป็นจุดเดียวที่พิสูจน์ว่า
`Scan` 34 คอลัมน์กับ 16 คอลัมน์เรียงตรงกับ `SELECT` — ถ้าเรียงผิดจะ 500 ทั้งหน้าโดย build ไม่ฟ้องอะไรเลย

## 4. migration บนฐานจริง

ฐาน dev/prod ตัวนี้ drift อยู่ก่อนแล้ว (`schema_migrations` = 12 แต่ตารางผู้ใช้ยังชื่อ `app_user`
ทั้งที่ migration 12 คือการเปลี่ยนชื่อเป็น `wbw_user` และตารางของ 13/15 หายไป) จึงต้อง
`migrate force V=11` แล้วรัน 12→16 ใหม่ · 13/14/15 เขียนแบบ `IF NOT EXISTS` จึงรันซ้ำได้ปลอดภัย

หลังรัน: `wbw_user` มี · `app_user` ไม่มีแล้ว · `wbw_staff`, `sos_feed_idx`, `group_membership_log`,
`idx_gml_user` ครบ · backfill ได้ `leave_quota = 0` ให้ 5 คนที่มีกลุ่มอยู่แล้ว และ `= 1` ให้คนที่ยังไม่มีกลุ่ม

สำรองก่อนแก้ไว้ที่ `~/sudb-before-quota-20260810-0413.sql` (205k, 29 ตาราง)

## 5. ที่ยังไม่ได้ทดสอบ

- **หน้า dashboard ทั้งหมด** — แผน `2026-08-09-group-leave-quota-dashboard.md` ยังไม่ได้ลงมือ
  คอลัมน์สิทธิ์ ตัวกรอง ช่องแก้ไข และไทม์ไลน์ยังไม่มีในเว็บ
- **`api.studentunion.social`** — `cloudflared` วน restart เพราะ `.env` ไม่มี `TUNNEL_TOKEN`
  แอปที่ตั้ง `.susProd` (ค่าที่จะขึ้น store) จึงยังต่อไม่ได้ ต้องใส่ token ก่อนทดสอบด้วยค่าจริง
- **push แจ้งเตือนเข้าแชท** — backend log เตือน `push ปิดอยู่: ไม่มี GOOGLE_APPLICATION_CREDENTIALS`
  เส้นทาง `.openGroupChat` → `tab = 3; groupPath = []` จึงยังไม่เคยถูกยิงด้วย push จริง
- **โควตาที่มากกว่า 1** — ทดสอบเฉพาะ 1 → 0 ยังไม่เคยลองค่า 2+ ที่แอดมินตั้งให้ (ข้อความรองรับแล้วและมี unit test
  แต่ยังไม่เคยเห็นบนจอ)
- **ผู้ใช้จำนวนมากพร้อมกัน** — ทดสอบด้วยบัญชีเดียว ฐานมีผู้เข้าร่วม 6 คน
