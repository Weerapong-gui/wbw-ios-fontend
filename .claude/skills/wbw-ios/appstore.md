# แก้อะไรก็ต้องคิดถึงขั้น App Store

ไฟล์นี้ตอบว่า **งานในโค้ดแบบไหน ลากของนอกโค้ดอะไรตามมาบ้าง** — ของนอกโค้ดคือสกรีนช็อต, App
description, Privacy Nutrition Label, เลข build, หน้าเว็บนโยบาย ซึ่งไม่มี build/test ตัวไหนจับให้

ทำไมต้องมี: รอบ 1.0 (7) โดนตีกลับ 2 ข้อเมื่อ 2026-08-09 (Guideline 2.1 กับ 2.3.3) **เพราะของนอกโค้ด
ไม่ขยับตามโค้ด** ไม่ใช่เพราะโค้ดผิด — สกรีนช็อตกับ description ยังโฆษณาฟีเจอร์ที่ถอดไปแล้ว และบัญชี
เดโม่ที่ Apple ถืออยู่ล็อกอินไม่ผ่าน · เสียไปหนึ่งรอบรีวิวเต็ม ๆ ต่อหนึ่งข้อ

ขั้นตอนกดจริงใน App Store Connect ไม่ได้อยู่ที่นี่ — อยู่ที่ `docs/appstore/connect-checklist.md`
(ลำดับอัปโหลด 1–8 ที่สลับแล้วโดนตีกลับซ้ำ + สถานะรอบปัจจุบัน) กับ `docs/appstore/README.md`
(วิธีถ่ายสกรีนช็อต) ไฟล์นี้ไม่คัดมาซ้ำ เพราะสองที่ที่เล่าเรื่องเดียวกันจะเน่าคนละทาง

## ตารางผลกระทบ — ทำอะไรแล้วต้องขยับอะไรตาม

| งานที่ทำในโค้ด | ของที่ต้องขยับตามในรอบเดียวกัน |
|---|---|
| เปลี่ยนหน้าตาจอที่อยู่ในชุดสกรีนช็อต (10 ใบตามตารางใน `docs/appstore/README.md`) | ถ่ายใหม่ตามขั้นตอนในไฟล์นั้น แล้วอัปมือใน ASC · เพดาน **10 ใบต่อขนาด** ตอนนี้เต็มพอดี เพิ่มใบใหม่ต้องถอดใบเก่าก่อน · รูปที่ไม่ตรงกับแอปจริงคือ **2.3.3** ที่เคยโดนมาแล้ว |
| ถอดฟีเจอร์ทิ้ง | App description **กับ** สกรีนช็อตต้องเลิกพูดถึงมันในรอบเดียวกัน · เคสจริง: SU RUN ถูกลบ 2026-08-22 แต่ description ยังโฆษณา "ติดตามระยะทาง/สะสมแต้ม" ค้างอยู่ = 2.3.3 |
| เพิ่มการเก็บ/ส่งข้อมูลผู้ใช้แบบใหม่ | ต้องตรงกัน **3 ที่**: `WBW/PrivacyInfo.xcprivacy` · Privacy Nutrition Label ใน ASC · หน้า `/privacy` บนเว็บ (repo `su-wbw-website`) — Apple เทียบสามอย่างนี้เอง ตอนนี้ประกาศ 5 ประเภท ทุกตัว Linked + ไม่ track + App Functionality |
| ใช้ framework ที่ต้องขอสิทธิ์ | `NS*UsageDescription` ต้องอยู่ครบ **ทั้ง** `WBW/Info.plist` และ `WBW/Info-Debug.plist` + คำแปลใน `WBW/th.lproj/InfoPlist.strings` กับ `WBW/en.lproj/InfoPlist.strings` + `xcodegen generate` ให้ไฟล์แปลเข้า .app จริง · ขาดคำแปลแล้วผู้ตรวจบนเครื่องภาษาอังกฤษเห็นกล่องเป็นไทย = **5.1.1** |
| ประกาศ background mode เพิ่ม | ต้องมีโค้ดรับมันจริง (`remote-notification` คู่กับ `didReceiveRemoteNotification`) · โหมดที่ไม่มีใครรับคือคำถามกลับตรง ๆ ตาม **2.5.4** |
| เพิ่มที่ที่ผู้ใช้เห็นเนื้อหาของผู้ใช้คนอื่น | UGC (**1.2**) ต้องครบสี่: บล็อก / ปลดบล็อก / รายงาน / ช่องทางติดต่อที่เผยแพร่ · แล้วต้องเขียนย่อหน้าชี้ทางให้ผู้ตรวจใน App Review Notes ด้วย ของมีในแอปแต่ผู้ตรวจหาไม่เจอ = โดนตีกลับเหมือนไม่มี · ทบทวน age rating ด้วย (ตอนนี้ **12+** เพราะแชทกลุ่ม ไม่ใช่ 4+) |
| แตะโหมดเดโม่ (`WBW/Demo/`) | ต้องคอมไพล์ติดใน **Release** เสมอ — ปุ่ม "ดูตัวอย่างแอป (Demo)" คือคำตอบของ **2.1** ห้ามย้ายเข้า `#if DEBUG` · และโหมดนี้ **ห้ามขอสิทธิ์อะไรเลย** กล่องที่เด้งขึ้นมาโดยไม่มีใครกดตอบจะค้างบังสกรีนช็อตทุกใบที่ถ่ายหลังจากนั้น (เคยเสีย 9 ใบจาก 10) |
| ลิงก์/URL ที่แอปพาออกเว็บ | ต้องตรงกับ Support URL / Privacy Policy URL ที่กรอกใน ASC · แถวพวกนี้จะอยู่ในบิลด์ก็ต่อเมื่อ **archive ใหม่** เท่านั้น |
| จะ archive ส่งขึ้น ASC | บั๊มเลข build ให้ครบ **3 ที่** (`project.yml` + สอง plist) · เลขซ้ำโดน ASC ปฏิเสธตั้งแต่ตอนอัป เสียรอบไปแล้ว |

**ถามสามข้อนี้ก่อนปิดงานทุกชิ้น:** จอที่แตะอยู่ในชุดสกรีนช็อตไหม · description ยังพูดความจริงอยู่ไหม ·
มีข้อมูล/สิทธิ์/โหมดอะไรเพิ่มที่ต้องประกาศไหม — ตอบว่า "ไม่มีผล" ได้ แต่ต้องตอบ

## ช่วงรออนุมัติ — ห้ามสามอย่าง

สถานะรอบปัจจุบันอ่านจากหัวข้อ "สถานะล่าสุด" ใน `docs/appstore/connect-checklist.md`
(ไฟล์นี้ไม่เก็บสถานะไว้ กันสองที่ขัดกัน) · ถ้าสถานะยังเป็น Waiting for Review / In Review:

1. **ห้ามลบหรือปิดบัญชีรีวิว** ออกจาก production — รอบ 1.0 (7) โดนตีกลับเพราะบัญชีหายไประหว่างรอ
2. **ห้ามเอาหน้า `/privacy` กับ `/support` ลง** และห้ามแก้ให้ขัดกับ Nutrition Label — Apple เปิดสองหน้านี้ระหว่างตรวจ
3. **ห้ามสลับ `Config.backend`** ที่ commit หรือปิด backend production — ค่าที่ค้างตอน push คือค่าที่ขึ้น store

จะส่ง build ใหม่ต้องกด "remove this version from review" ใน ASC ก่อน · ระหว่างรอ แก้เมทาดาทาบางช่องได้
แต่เปลี่ยน build ไม่ได้ · **งานเอกสาร/สคริปต์ที่ไม่แตะ `WBW/` ทำได้ตามปกติ** ไม่กระทบบิลด์ที่ส่งไปแล้ว

## อะไรที่เครื่องจับให้แล้ว อะไรที่ต้องใช้ตาคน

จับให้แล้ว — `WBWTests/AppStoreConfigTests.swift` คุมเลข build ทั้งสามที่, plist สอง config ที่ต้อง
ต่างกันเฉพาะคีย์ของ dev, `NS*UsageDescription` + คำแปลสองภาษา + ไฟล์แปลถูกแพ็กเข้า .app จริง,
background mode คู่กับ handler, privacy manifest (ห้ามประกาศเกิน/ขาด), `aps-environment` ของสอง
entitlements · `WBWTests/DemoPermissionTests.swift` กันโหมดเดโม่ขอสิทธิ์ ·
`WBWTests/SettingsLinksTests.swift` กัน URL ในหน้าตั้งค่าเพี้ยนจากที่กรอกใน ASC ·
`scripts/check-skill-refs.sh` หัวข้อ "ผลกระทบต่อ App Store" เทียบเลข build กับเอกสารรอบส่ง และเช็กว่า
แฟลกที่ใช้ถ่ายสกรีนช็อตยังมีอยู่ในโค้ด

**จับให้ไม่ได้เลย** — เนื้อสกรีนช็อตตรงกับแอปไหม, App description พูดความจริงไหม, Nutrition Label ใน
ASC ตรงกับ manifest ไหม, ย่อหน้า UGC อยู่ใน Review Notes จริงไหม · สี่อย่างนี้เป็นตาคนล้วน และทั้งสี่คือ
สิ่งที่ทำให้โดนตีกลับมาแล้ว
